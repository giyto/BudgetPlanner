## Context

Мотивация — в `proposal.md`, требования — в `specs/`. Что уже есть:

- Расчёт «можно сегодня» — `ObservePeriodStatus` / `BudgetCalculator`; смена дня в приложении уже обрабатывается (`MidnightFlowTest`), но только пока приложение открыто.
- Операции из уведомлений приходят через `BankNotificationListener` → `NotificationIntake` (сервис живёт в процессе приложения и сам открывает базу через `DatabaseAccess.open()`).
- Образцы уведомлений чистятся в `NotificationIntake.purgeExpiredSamples()` только при приходе нового уведомления.
- Расхождения — `ObserveMismatches`; предложение нового периода — `IncomePeriodSuggestion` и `PeriodStatus.isIncomeDue`.
- Защита входа — `LockSettingsRepository` (`enabled`), блокировка — `AppLock` в активности.
- Онбординг: шаги `INTRO, MONEY, PAYMENTS, AUTO_IMPORT, PROTECTION`.
- Glance и WorkManager в проекте не подключены.

## Goals / Non-Goals

**Goals:**
- Виджет и уведомления работают при закрытом приложении, база при этом открывается тем же `DatabaseAccess`.
- Решение «присылать или нет» — чистая логика в `domain`, проверяемая unit-тестами на фиксированных часах.
- Ни одно уведомление не приходит дважды по одной причине.

**Non-Goals:**
- Настройка времени напоминаний пользователем (выбрано фиксированное 10:00).
- Интерактивные действия прямо в уведомлении («Отметить оплаченным» и т.п.).
- Виджет с прокручиваемым списком операций, несколько разных виджетов.
- Уведомления о каждой операции из банка (их и так присылает банк).

## Decisions

### 1. Виджет — `GlanceAppWidget` с `SizeMode.Responsive` на два размера

Размеры 110×40 dp (маленький, 2×1) и 250×110 dp (средний, 4×2). Содержимое считается в `WidgetSnapshot` (domain): состояние «нет данных», «скрыто», «показано» с суммой, долей лимита и днями до дохода. Glance получает данные через Hilt `EntryPoint` (`WidgetEntryPoint`), открывает базу `DatabaseAccess.open()` и берёт одно значение `ObservePeriodStatus().first()`; при `KEY_LOST`/`ERROR` или без периода — «Откройте BudgetPlanner». Цвета — из палитры проекта через `ColorProviders` для светлой и тёмной темы.

*Альтернатива:* классический `AppWidgetProvider` с `RemoteViews`. Отвергнута: стек проекта — Compose, Glance даёт адаптивные размеры без отдельной XML-разметки.

### 2. Обновление виджета — `WidgetRefresher` за интерфейсом в `domain`

Интерфейс `WidgetRefresher.refresh()`, реализация вызывает `BudgetWidget().updateAll(context)`. Вызывается: после импорта операции в `NotificationIntake` (требование 3 секунд), из приложения — коллектором `ObservePeriodStatus` в `AppRootViewModel` (любое изменение операций, периода, платежей пересчитывает статус), при смене настройки защиты входа, фоновой задачей смены дня.

*Альтернатива:* `InvalidationTracker` Room. Отвергнута: виджету нужна не таблица, а итог расчёта, и коллектор статуса уже даёт ровно это.

### 3. Решение об уведомлениях — `NotificationPlanner` (domain), состояние «уже отправлено» — DataStore

Чистая функция по `PeriodStatus`, платежам, расхождениям, предложению нового периода, настройкам типов и журналу отправленного возвращает список уведомлений к показу. Журнал в DataStore: дата последнего перерасхода, отправленные напоминания (`id платежа + дата`), id периода для «дня дохода» и «пришло N ₽», ключи отправленных расхождений (`счёт + момент расхождения`). Так «не чаще раза в день» и «один раз на причину» проверяются unit-тестами без Android.

Use case `CheckNotifications(now)` берёт данные, вызывает планировщик, отдаёт результат `AppNotifier` (интерфейс в domain, реализация на `NotificationManagerCompat`) и записывает журнал. Вызывается после импорта в `NotificationIntake`, после сохранения операции в приложении (тот же коллектор статуса, что и для виджета, с дедупликацией по журналу) и фоновыми задачами.

### 4. Фоновые задачи — WorkManager с Hilt

- `DailyWork` — уникальная `OneTimeWorkRequest`, переназначающая себя на следующее 10:00 по `Clock` (точное время не гарантируется, задержка до нескольких минут допустима): напоминания о платежах на завтра, «наступил день дохода», очистка образцов старше 24 часов, обновление виджета.
- `MidnightWork` — так же на 00:01: обновление виджета и проверка дня дохода для плашки.
- Обе ставятся при старте приложения (`BudgetApplication.onCreate`) с `ExistingWorkPolicy.KEEP` и после загрузки телефона — WorkManager сам восстанавливает работы. Если телефон был выключен в 10:00, работа выполнится при включении; «не после даты платежа» проверяет планировщик по дате.

*Альтернатива:* `AlarmManager.setExact`. Отвергнута: требует разрешения на точные будильники (Android 12+) ради точности, которая напоминанию не нужна.

### 5. Каналы и содержимое уведомлений

Четыре канала: `overspend`, `payments`, `new_period`, `bank_mismatch` с русскими названиями, важность «по умолчанию». Нажатие — `PendingIntent` в `MainActivity` с действием (`open_new_period`, `open_reconcile`, `open_home`). Если включена защита входа, `setVisibility(VISIBILITY_PRIVATE)` и публичная версия «BudgetPlanner · новое уведомление». В тексте — только суммы, название платежа и «Банк *1234».

### 6. Переходы из виджета и уведомлений — действие в `Intent`, разбор в `MainActivity`

`MainActivity` читает `intent.action` (`ACTION_ADD_EXPENSE`, `ACTION_NEW_PERIOD`, `ACTION_RECONCILE`) и передаёт в навигацию одноразовое событие после разблокировки (через `AppRootViewModel`). Прямые deep links из других приложений не принимаются: действия разрешены только из явных `PendingIntent` самого приложения (`FLAG_IMMUTABLE`, явный компонент).

### 7. Разрешение и настройки

Шаг онбординга `NOTIFICATIONS` между `AUTO_IMPORT` и `PROTECTION`, показывается только при SDK ≥ 33 и невыданном разрешении; запрос через `ActivityResultContracts.RequestPermission`. Раздел «Уведомления» в настройках: четыре переключателя (DataStore, по умолчанию включены) и, если разрешения нет, строка с кнопкой «Разрешить»: системный запрос, а если система его больше не показывает (`shouldShowRequestPermissionRationale == false` после отказа) — `Settings.ACTION_APP_NOTIFICATION_SETTINGS`.

## Risks / Trade-offs

- [MIUI и другие оболочки откладывают или убивают фоновые задачи] → автозапуск уже настраивается на шаге автоимпорта; на телефоне проверяется приход напоминания в 10:00 (задача ручной проверки). Если откладывается, напоминание всё равно придёт при следующем запуске в тот же день.
- [Перерасход из ручной траты считается в приложении, а не в фоне] → приложение в этот момент открыто, коллектор статуса работает; для импорта проверка вызывается из `NotificationIntake`.
- [Виджет на холодном старте процесса открывает базу] → `DatabaseAccess.open()` не требует разблокировки пользователем (ключ не привязан к биометрии), это уже делает сервис автоимпорта.
- [Сумма на рабочем столе] → при защите входа скрывается (spec home-widget).

## Migration Plan

Схема базы не меняется. Новые настройки в DataStore со значениями по умолчанию. Существующие пользователи (онбординг пройден) увидят раздел «Уведомления» в настройках; шаг онбординга для них не показывается.
