## Why

Приложение не видит счёт и может разойтись с ним: оплата наличными, пропущенное уведомление, комиссия, автоплатёж без пуша. Сверка с остатком из уведомлений банка находит расхождение и помогает его исправить (FR-13, сценарий 5.9).

## What Changes

- `BalanceReconciler`: ожидаемый остаток от точки отсчёта, порог расхождения 1 ₽, раздельная сверка карт по последним 4 цифрам.
- Плашка «Расхождение с банком N ₽» на главной по макету `MainMismatch.dc.html`.
- Экран сверки по макету `Reconcile.dc.html`: корректировка в обе стороны, переход к операциям периода, пропуск. Корректировка создаётся только с подтверждения пользователя.
- Новая точка отсчёта после решения.
- Ручная сверка кнопкой «Сверить с банком» на экране периода, время последней сверки.
- Настройка «автоматическая сверка» в настройках.

## Capabilities

### New Capabilities
- `balance-reconciliation`: точка отсчёта, ожидаемый остаток, обнаружение расхождения, корректировки, ручная сверка.

### Modified Capabilities
- `home-screen`: добавляется плашка расхождения.
- `operations`: появляется тип «корректировка», входящий в расчёт «можно сегодня».

## Impact

- Пакеты `domain/budget` (`BalanceReconciler`), `ui/reconcile`, `ui/period`.
- Зависит от разбора остатка на этапе `add-notification-import`. Открытый вопрос **6** раздела 17: если банк не пишет остаток, остаётся только ручная сверка. Вопрос **4** (общий бюджет по нескольким картам или раздельный) влияет на отображение.
- Unit-тесты по списку раздела 13.1.
