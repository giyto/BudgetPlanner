## Why

Приложение не видит счёт и может разойтись с ним: оплата наличными, пропущенное уведомление, комиссия, автоплатёж без пуша. Тогда «можно сегодня» врёт, и пользователь перестаёт ему верить. Сверка с остатком банка находит расхождение и помогает его исправить (FR-13, сценарий 5.9). Остатки из уведомлений уже сохраняются с этапа `add-notification-import`, но пока нигде не используются.

## What Changes

- Расчёт ожидаемого остатка по каждой карте от точки отсчёта: пополнения и списания по этой карте после неё, включая черновики и обе стороны перевода себе.
- Автоматическая сверка: каждый новый остаток из уведомления сравнивается с ожидаемым; первый остаток карты становится точкой отсчёта; разница до 1 ₽ включительно молча сдвигает точку отсчёта.
- Плашка «Расхождение с банком N ₽» на главной по макету `MainMismatch`: одна карта — суммы банка и приложения, несколько карт — число карт с расхождением.
- Экран «Сверка с банком» по макетам `Reconcile` (одна карта) и `ReconcileCards` (несколько карт): записать корректировку, найти пропущенную операцию, пропустить, ввести остаток вручную.
- Корректировка — новый источник операции: банк показывает меньше — трата «Другое», больше — доход «Другие доходы»; создаётся только по нажатию пользователя и входит в «можно сегодня» как обычная операция.
- «Найти пропущенную операцию» открывает список операций с фильтром по карте и дате прошлой сверки.
- Ручная сверка: кнопка «Сверить с банком» и время последней сверки на экране периода; выбор карты или счёта без автоимпорта, ввод реального остатка, дальше тот же сценарий.
- Переключатель «Автоматическая сверка» в настройках, по умолчанию включён.
- Инструмент разработки «Фейковый банк»: отдельное отладочное приложение для эмулятора, которое присылает уведомления от имени пакета банка, чтобы пройти сверку без настоящих операций. В сборку BudgetPlanner не входит.

## Capabilities

### New Capabilities
- `balance-reconciliation`: точка отсчёта, ожидаемый остаток по карте, обнаружение расхождения, экран сверки, корректировки, ручная сверка, настройка автоматической сверки.

### Modified Capabilities
- `home-screen`: добавляется плашка расхождения с банком.
- `operations`: появляется источник «корректировка» и фильтр «карта с даты» для поиска пропущенной операции.
- `budget-period`: на экране периода появляются кнопка «Сверить с банком» и время последней сверки.

## Impact

- `domain/budget` (`BalanceReconciler`, расчёт ожидаемого остатка), `domain/usecase` (сверка после импорта, корректировка, ручная сверка).
- Room: таблица состояния сверки по картам, источник операции «корректировка», миграция 4 → 5; запросы операций по карте после момента времени.
- `ui/reconcile` (новый экран), `ui/home` (плашка), `ui/period` (кнопка и время сверки), `ui/operations` (фильтр по карте), `ui/settings` (переключатель); DataStore для настройки.
- Макеты в `docs/design`: `MainMismatch`, `Reconcile`, `ReconcileCards` и новые для этого этапа `MainMismatchCards`, `PeriodReconcile`, `ReconcileManual`, `OperationsCardFilter`, `AddForCard`, `SettingsReconcile` (исходник `mockups/Reconciliation.html`), светлая и тёмная темы.
- Новый gradle-модуль `tools/fakebank` (только отладка, только эмулятор).
- Открытый вопрос **6** раздела 17 остаётся открытым: в двух настоящих уведомлениях Альфы остатка нет; для Сбера и Т-Банка настоящих образцов ещё нет. Если банк не пишет остаток, для его карт работает только ручная сверка — это поведение заложено в спецификацию.
- Уведомление приложения о расхождении (FR-12) делается на этапе `add-widget-and-reminders`.
