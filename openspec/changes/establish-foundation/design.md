## Context

Проект создан из шаблона Android Studio «Empty Activity»: один модуль `app`, AGP 9.3.3, Kotlin 2.2.10, Compose BOM 2026.02.01, `compileSdk`/`targetSdk` 37, `minSdk` 29, Gradle 9.5, JDK 25 для демона. В шаблоне включены динамические цвета, фиолетовая палитра, XML-тема `android:Theme.Material.Light.NoActionBar` без тёмного варианта и `compileOptions` на Java 11. Hilt, KSP, навигации и тестовых библиотек кроме JUnit и Espresso нет.

Требования к результату: specs `app-theme`, `app-navigation`, `app-foundation`. Мотивация: proposal.md.

## Goals / Non-Goals

**Goals:**
- Каркас, в который следующие этапы добавляют экраны и данные, не трогая инфраструктуру.
- Тема, в которой токены макетов доступны экранам по имени, включая цвета, которых нет в Material 3 (главная карточка, «осталось», перерасход, цвета категорий).
- Сборка и тесты, которые одинаково проходят на API 29 и API 37.

**Non-Goals:**
- Содержимое экранов: главная, операции и остальные остаются заглушками с заголовком.
- База данных, DataStore, шифрование, исключение из автобэкапа (`allowBackup` не трогаем до этапа `add-data-protection`).
- Деление на Gradle-модули.

## Decisions

### 1. Один модуль `app`, слои разделены пакетами
Пакеты по разделу 8.2 ТЗ. Чистота доменного слоя проверяется unit-тестом, который проходит по исходникам `domain` и падает при импорте `android.*` или `androidx.*`.
- *Альтернатива:* отдельный JVM-модуль `:domain`. Надёжнее, но удваивает настройку сборки ради одного правила. Вернуться к ней можно на любом этапе, перенос пакета в модуль механический.

### 2. Сборка: встроенный Kotlin AGP 9, KSP, Hilt
AGP 9 сам подключает Kotlin, плагин `org.jetbrains.kotlin.android` не добавляется. Подключаются KSP 2.3.6 и Hilt 2.59.2 (обе версии поддерживают AGP 9 и встроенный Kotlin), плагин сериализации Kotlin для типобезопасных маршрутов. `compileOptions` и `jvmToolchain` поднимаются до Java 17.
- В ТЗ указан AGP 9.3.2, в проекте уже 9.3.3. Оставляем 9.3.3: это патч-версия той же линии, таблицу 9.1 ТЗ можно поправить при следующей правке документа.
- Если на этапе синхронизации окажется, что одна из версий из таблицы 9.1 несовместима, берётся ближайшая совместимая и фиксируется в `libs.versions.toml` с комментарием.

### 3. Навигация: Navigation Compose 2.10 с типобезопасными маршрутами
Маршруты описываются `@Serializable`-объектами. Четыре раздела — вложенные графы верхнего уровня. Переход по вкладке делается с `popUpTo(startDestination) { saveState = true }`, `launchSingleTop = true`, `restoreState = true`: так каждый раздел хранит свой стек и состояние, а «Назад» из любого раздела ведёт на главную. Экраны «Новая операция» и «Настройки» лежат в корневом графе вне разделов, поэтому нижняя панель на них не показывается: её видимость вычисляется по текущему маршруту.
- *Альтернатива:* Navigation 3. Новее и проще для собственных стеков, но в ТЗ зафиксирована Navigation Compose 2.10, и для четырёх вкладок с заглушками её возможностей хватает.

### 4. Тема: свои токены поверх Material 3
`BudgetColors` — неизменяемый класс со всеми токенами палитры макетов (объект `THEMES` в `docs/design/mockups/Main.dc.html`) в двух экземплярах, светлом и тёмном. Он раздаётся через `CompositionLocal` и доступен как `BudgetTheme.colors`. Из него же строится `ColorScheme` Material 3, чтобы стандартные компоненты (кнопки, панель навигации) получали правильные цвета без ручной настройки. Динамические цвета не используются.
- *Альтернатива:* только `ColorScheme`. Не хватает слотов для «осталось», перерасхода, резерва и цветов категорий, пришлось бы занимать `tertiary` и подобные слоты не по смыслу.

### 5. Шрифты в составе приложения
Статические TTF Onest (400, 500, 600, 700) и Unbounded (500, 600, 700) лежат в `res/font`, рядом текст лицензии SIL OFL 1.1. `Typography` Material 3 задаётся из макетов: заголовки и крупные суммы Unbounded, остальное Onest.
- *Альтернатива:* загружаемые шрифты Google Fonts. Требуют Google Play Services и сеть при первом запуске, что противоречит работе без интернета и мешает публикации вне Google Play.

### 6. Источник времени: `java.time.Clock` через Hilt
Hilt отдаёт `Clock` с часовым поясом, который определяется при каждом обращении (`ZoneId.systemDefault()`), поэтому смена пояса на телефоне сразу учитывается. Доменный код принимает `Clock` в конструкторе, тесты передают `Clock.fixed(...)`. `java.time` доступен на API 26+, desugaring не нужен.
- *Альтернатива:* `Clock.systemDefaultZone()`. Запоминает пояс в момент создания и после смены пояса показывает неверную дату до перезапуска процесса.

### 7. Окно при запуске
XML-тема наследует `android:Theme.Material.Light.NoActionBar`, вариант в `values-night` — `android:Theme.Material.NoActionBar`. `windowBackground` в обоих равен цвету фона палитры, поэтому до первого кадра Compose окно уже нужного цвета. Edge-to-edge включён (`enableEdgeToEdge`), отступы под системные панели даёт `Scaffold`.

### 8. Тесты
- Unit (JVM): источник времени, правило чистоты `domain`.
- Instrumented (Compose UI Test, `createAndroidComposeRule<MainActivity>`): запуск на главной, переходы по вкладкам, «Назад», открытие «+» и настроек, сохранение вкладки после пересоздания активности, описания для TalkBack.
- Подмена зависимостей Hilt в UI-тестах на этом этапе не нужна: заглушки не имеют зависимостей. `HiltTestApplication` и свой test runner подключаются на этапе, где появятся первые ViewModel с данными.
- Прогон на двух эмуляторах вручную: `connectedDebugAndroidTest` по очереди на API 29 и API 37.

## Risks / Trade-offs

- [Связка AGP 9 + встроенный Kotlin + KSP + Hilt новая, возможны ошибки синхронизации] → подключать по одному плагину с проверкой `assembleDebug` после каждого шага (см. tasks.md).
- [Два эмулятора одновременно тяжелы для 16 ГБ памяти] → тесты на API 29 и API 37 запускаются по очереди, второй эмулятор не держится открытым постоянно.
- [Правило чистоты `domain` проверяется тестом, а не компилятором] → тест входит в обычный `testDebugUnitTest`, нарушение видно при каждом прогоне.
- [Шрифты увеличивают размер APK на 0,5–1 МБ] → берутся только нужные начертания, кириллица и латиница.

## Migration Plan

Приложение ещё не опубликовано, данных пользователей нет. Шаблонный код удаляется без миграции. Откат — возврат к предыдущему коммиту.
