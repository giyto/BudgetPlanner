## ADDED Requirements

### Requirement: Release-сборка
Release-сборка SHALL быть оптимизирована (сжатие кода и ресурсов), иметь версию 1.0 и подписываться ключом пользователя. Ключ подписи и пароли к нему MUST храниться вне git и вводиться только пользователем. В release-сборке MUST NOT быть раздела «Для разработки» (демо-данные, сбор образцов уведомлений), а журнал MUST NOT содержать сумм, магазинов, текстов уведомлений и ключей. Все экраны и фоновые функции (автоимпорт, напоминания, виджет, ИИ-помощник) MUST работать в release-сборке так же, как в отладочной.

#### Scenario: Сборка версии 1.0
- **WHEN** пользователь собирает release-версию со своим ключом подписи
- **THEN** получается установочный файл версии 1.0, подписанный ключом пользователя; в репозитории нет ни ключа, ни паролей

#### Scenario: Release на телефоне
- **WHEN** release-версия установлена на телефон
- **THEN** онбординг, главная, операции, черновики, статистика, помощник, виджет и уведомления работают, раздела «Для разработки» в настройках нет

### Requirement: Разрешения собранного приложения
Собранное приложение SHALL запрашивать только разрешения из раздела 11 ТЗ и служебные разрешения библиотек без доступа к данным пользователя (фоновые задачи, биометрия). Из сетевых разрешений MUST быть только `INTERNET`; разрешений на SMS, контакты, память телефона и местоположение MUST NOT быть.

#### Scenario: Проверка установочного файла
- **WHEN** проверяется список разрешений release-сборки
- **THEN** в нём нет `READ_SMS`, `ACCESS_NETWORK_STATE`, разрешений памяти и местоположения; из сетевых есть только `INTERNET`
