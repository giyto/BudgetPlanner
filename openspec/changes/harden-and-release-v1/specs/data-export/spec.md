## Purpose

Данные пользователя можно выгрузить в таблицу, сохранить в зашифрованную резервную копию и восстановить из неё на этом или новом телефоне, а также полностью удалить с телефона (FR-11, раздел 7.9 ТЗ).

## ADDED Requirements

### Requirement: Раздел «Данные» в настройках
В настройках SHALL быть раздел «Данные» с действиями «Экспорт в CSV», «Резервная копия», «Восстановить из копии» и «Удалить все данные». Раздел MUST быть оформлен как остальные разделы настроек по макету.

#### Scenario: Открытие раздела
- **WHEN** пользователь открывает настройки и прокручивает к разделу «Данные»
- **THEN** видны четыре действия, «Удалить все данные» выделено цветом предупреждения

### Requirement: Экспорт операций в CSV
Приложение SHALL выгружать операции за выбранные даты в файл CSV, который пользователь сохраняет через системный выбор места. По умолчанию выбраны даты текущего периода. Файл MUST открываться в Excel и «Google Таблицах» без настройки: кодировка UTF-8 с меткой BOM, разделитель «;», сумма в рублях с запятой и знаком («-450,00» для трат, «12000,00» для доходов; знак — обычный дефис-минус, иначе таблица прочитает сумму как текст). Столбцы: дата, время, тип, сумма, категория, магазин или описание, комментарий, источник (вручную, уведомление банка, корректировка), банк, черновик. Последние цифры карт MUST NOT попадать в файл. Приложение не запрашивает доступ к памяти телефона.

#### Scenario: Экспорт текущего периода
- **WHEN** пользователь выбирает «Экспорт в CSV», оставляет даты периода 1–25 октября и сохраняет файл в «Загрузки»
- **THEN** в файле все операции с 1 по 25 октября, по одной строке на операцию, в том числе черновики и переводы себе, и строка заголовков

#### Scenario: Нет операций за даты
- **WHEN** за выбранные даты операций нет
- **THEN** приложение сообщает «Нет операций за эти даты», файл не создаётся

#### Scenario: Пользователь закрыл выбор места
- **WHEN** пользователь закрыл системный выбор места, не сохранив файл
- **THEN** ничего не создаётся и сообщений об ошибке нет

### Requirement: Защита от формул в CSV
Текстовые ячейки (категория, магазин, комментарий), которые начинаются с «=», «+», «−», «-» или «@», SHALL выгружаться с апострофом в начале, чтобы таблица не выполнила их как формулу.

#### Scenario: Магазин похож на формулу
- **WHEN** в операции магазин «=HYPERLINK(...)»
- **THEN** в файле ячейка «'=HYPERLINK(...)», таблица показывает её как текст

### Requirement: Резервная копия
Приложение SHALL сохранять все данные в один файл резервной копии в месте, которое выбирает пользователь. В копию MUST входить операции, категории, периоды, обязательные платежи, правила для магазинов, состояние сверки с банком, история ИИ-помощника и настройки (расписание дохода, защита входа, сверка, ИИ-помощник, уведомления, имена для переводов себе). В копию MUST NOT входить то, что относится к конкретному телефону: ключ шифрования базы, отметки настройки автоимпорта, системные разрешения, счётчик токенов «на этом телефоне», журнал отправленных уведомлений и образцы уведомлений. Файл MUST быть зашифрован паролем, который пользователь вводит дважды; пароль не короче 8 символов и нигде не сохраняется. Незашифрованные данные MUST NOT оставаться на телефоне вне базы после создания копии.

#### Scenario: Создание копии
- **WHEN** пользователь выбирает «Резервная копия», дважды вводит пароль «осень2026!» и сохраняет файл
- **THEN** создаётся файл «budget-backup-2026-10-17.bpbackup», приложение сообщает «Копия сохранена»

#### Scenario: Пароли не совпадают
- **WHEN** пароль и повтор пароля различаются или пароль короче 8 символов
- **THEN** кнопка сохранения недоступна, под полем объясняется причина

#### Scenario: Файл без пароля не читается
- **WHEN** файл копии открывают на компьютере без пароля
- **THEN** ни операции, ни суммы, ни названия магазинов прочитать нельзя

### Requirement: Восстановление из копии
Приложение SHALL восстанавливать данные из файла копии после ввода пароля и подтверждения, что текущие данные будут заменены целиком. После восстановления приложение перезапускается и показывает данные из копии. Копия из более старой версии приложения MUST восстанавливаться с переносом данных в текущий формат. Неверный пароль, повреждённый или чужой файл и копия из более новой версии MUST NOT менять текущие данные.

#### Scenario: Перенос на новый телефон
- **WHEN** на новом телефоне после установки пользователь выбирает «Восстановить из копии», указывает файл, вводит пароль и подтверждает замену
- **THEN** приложение перезапускается и показывает главный экран с операциями, периодом и настройками из копии, онбординг не показывается

#### Scenario: Неверный пароль
- **WHEN** пользователь вводит неверный пароль
- **THEN** приложение сообщает «Неверный пароль или файл повреждён», текущие данные не меняются

#### Scenario: Копия из новой версии
- **WHEN** файл создан более новой версией приложения
- **THEN** приложение сообщает «Копия создана более новой версией приложения, обновите приложение», данные не меняются

#### Scenario: Защита входа на телефоне без блокировки экрана
- **WHEN** в копии включена защита входа, а на новом телефоне нет блокировки экрана
- **THEN** защита выключается сама с сообщением, как при снятии блокировки экрана

### Requirement: Удаление всех данных
«Удалить все данные» SHALL после подтверждения удалить с телефона базу, её ключ, все настройки приложения, образцы уведомлений и показанные уведомления приложения, затем перезапустить приложение в онбординг. Диалог подтверждения MUST назвать последствия и предложить сначала сделать резервную копию. Разрешения, выданные в настройках Android (доступ к уведомлениям, уведомления приложения), остаются: приложение не может их отозвать.

#### Scenario: Удаление
- **WHEN** пользователь выбирает «Удалить все данные» и подтверждает
- **THEN** приложение перезапускается и показывает первый шаг онбординга, операций и настроек нет, виджет показывает «Нет данных»

#### Scenario: Отмена
- **WHEN** пользователь закрывает диалог подтверждения кнопкой «Отмена»
- **THEN** данные не меняются
