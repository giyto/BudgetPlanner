## Why

Пользователь хочет задавать вопросы о расходах обычным языком: «хватит ли до стипендии, если куплю наушники за 3000?» (задача 5 раздела 2 ТЗ, сценарий 5.7). При этом финансовые данные не должны уходить в модель целиком.

## What Changes

- Интерфейс `LlmProvider` в `domain` и реализация для GigaChat: получение и обновление токена, запросы к модели, вызов функций.
- Локальные инструменты, которые только читают данные: `get_period_status`, `get_spending`, `get_spending_by_category`, `get_top_merchants`, `simulate_purchase`, `compare_periods` (FR-08).
- Цикл «запрос → вызов функции → результат → ответ», не больше 5 вызовов на вопрос (8.3).
- Экран чата по макету `Assistant.dc.html`: история диалогов локально, подсказки вопросов, индикатор токенов.
- ИИ выключен по умолчанию; при включении показывается, какие данные уходят в модель. Режим «не отправлять названия магазинов».
- Ключ авторизации GigaChat вводится пользователем и хранится зашифрованным ключом Keystore.
- Учёт токенов и предупреждение у лимита бесплатного тарифа; понятные сообщения при ошибке сети и исчерпанном лимите.
- Предложение категории для черновика моделью, применяется только с подтверждения (FR-06).

## Capabilities

### New Capabilities
- `ai-assistant`: чат, инструменты, ограничения на передаваемые данные, учёт токенов, обработка ошибок.

### Modified Capabilities
- `app-foundation`: появляется разрешение `INTERNET`, используется только при включённом ИИ.
- `auto-categorization`: добавляется предложение категории моделью.

## Impact

- Новые зависимости: Ktor Client с движком OkHttp, kotlinx.serialization (JSON), Ktor MockEngine для тестов.
- Сертификат НУЦ Минцифры в `res/raw`, `network_security_config` с `domain-config` только для доменов GigaChat.
- Пакеты `ai`, `ai/gigachat`, `ai/tools`, `ui/assistant`.
- Доступность бесплатного тарифа для новых клиентов проверяется при регистрации (9.3 ТЗ).
- **Статус:** черновик. Specs, design и tasks пишутся в начале этапа.
