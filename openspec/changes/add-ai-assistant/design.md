## Context

Мотивация — в `proposal.md`, требования — в `specs/`. Что уже есть:

- Раздел «Помощник» в нижней панели — заглушка `ui/assistant/AssistantScreen`, пакет `ai` пустой.
- Расчёты, которые нужны инструментам, уже есть: `ObservePeriodStatus` и `BudgetCalculator` (состояние периода, гипотетическая покупка), `StatisticsRepository` (траты по категориям, магазины, итоги за интервал), `ObserveSpendingComparison` и `ObservePastPeriods` (сравнение с прошлым периодом).
- База Room версии 6 под SQLCipher; настройки — DataStore `settings` с отдельными модулями привязок для тестов.
- Экран черновиков уже умеет показывать предварительную категорию с пометкой (подсказка словаря, add-auto-categorization).
- В манифесте нет `INTERNET`, сетевого стека в проекте нет.
- GigaChat API (проверено по документации): токен — `POST https://ngw.devices.sberbank.ru:9443/api/v2/oauth` (`Authorization: Basic <ключ>`, `RqUID`, `scope=GIGACHAT_API_PERS`), живёт 30 минут, `expires_at` в миллисекундах; модель — `POST https://api.giga.chat/v1/chat/completions` (с 17.07.2026 это целевой адрес для всех). Функции: поле `functions`, `function_call: "auto"`, ответ с `finish_reason: "function_call"`, `message.function_call {name, arguments}` и `functions_state_id`; результат — сообщение `role: "function"` с JSON-строкой в `content`. Ошибки: 401 — ключ или токен, 402 — закончились токены, 429 — частота запросов. `GET /balance` работает только для купленных пакетов.

## Goals / Non-Goals

**Goals:**
- Модель заменяема: остальной код зависит только от `LlmProvider` в `domain`.
- Цикл, инструменты и разбор ошибок тестируются без сети: цикл — с подменным `LlmProvider`, клиент — через Ktor `MockEngine`.
- В модель уходят только результаты инструментов; что именно уходит, видно в коде одного места (сериализация результатов инструментов).

**Non-Goals:**
- Потоковые ответы (SSE), голосовой ввод, вложения.
- Изменение данных через помощника (раздел 15 ТЗ).
- Другие провайдеры (YandexGPT, локальная модель) — только точка расширения.
- Несколько сохранённых диалогов — выбран один диалог с «Новым диалогом».

## Decisions

### 1. `LlmProvider` в domain — один шаг диалога, без цикла

```kotlin
interface LlmProvider {
    suspend fun complete(messages: List<LlmMessage>, tools: List<ToolSpec>): LlmResult
    suspend fun checkKey(key: String): KeyCheck
}
```

`LlmMessage` — роли `SYSTEM`, `USER`, `ASSISTANT` (текст или вызов функции с `stateId`), `FUNCTION` (имя и JSON-строка). `LlmResult` — `Text(content, usage)`, `ToolCall(name, argumentsJson, stateId, usage)` или `Failure(LlmError)`, где `LlmError` — `NoNetwork`, `BadKey`, `TokensExhausted`, `RateLimited`, `Unavailable`. Аргументы и результаты — JSON-строки: domain не зависит от kotlinx.serialization, разбор живёт в `ai`.

*Альтернатива:* провайдер сам гоняет цикл функций. Отвергнута: цикл и ограничение в 5 вызовов — правило приложения, а не провайдера; при замене модели его пришлось бы повторять.

### 2. Цикл и инструменты — в пакете `ai`

`AssistantEngine.ask(history, question)`: системный промпт + последние 10 сообщений диалога + вопрос → `complete` → если `ToolCall`, выполняется инструмент из реестра, результат добавляется сообщениями `ASSISTANT(function_call)` и `FUNCTION`, запрос повторяется. Шестой вызов не выполняется — `AssistantAnswer.TooManyCalls`. Итог: текст ответа, список выполненных инструментов (для подписи «Посчитал по вашему бюджету»), сумма токенов.

Инструменты — классы `AssistantTool { name; description; parametersSchema; suspend fun run(args: JsonObject): JsonObject }`, собираются в `Set` через Hilt `@IntoSet`. Реестр отдаёт модели описания с учётом настройки «Не отправлять названия магазинов» (без `get_top_merchants`). Суммы на границе инструмента переводятся из копеек в рубли числом с двумя знаками; даты — ISO `yyyy-MM-dd`, по умолчанию интервал текущего периода. Ошибка инструмента (неизвестная категория, неверная дата) возвращается модели как `{"error": "..."}`, а не исключением.

`simulate_purchase(amount)` считает `BudgetCalculator.calculate` с добавленной гипотетической тратой сегодня и возвращает «можно сегодня», завтрашний лимит, остаток периода и признак перерасхода. `compare_periods` — `ObserveSpendingComparison` для текущего и прошлого завершённого периода.

### 3. Клиент GigaChat — Ktor с движком OkHttp

`GigaChatAuth` хранит токен в памяти и обновляет его за минуту до `expires_at`; при 401 от модели токен сбрасывается и запрос повторяется один раз. `GigaChatClient` маппит DTO (kotlinx.serialization, `ignoreUnknownKeys`) в `LlmResult`. Таймаут запроса 60 с. Один запрос за раз (`Mutex`): бесплатный тариф даёт один поток. Плагин логирования Ktor не подключается. Модель — константа (см. открытые вопросы).

Движок OkHttp выбран, потому что он учитывает `network_security_config`; конфиг добавляет корневой сертификат НУЦ Минцифры из `res/raw` в `domain-config` только для `ngw.devices.sberbank.ru` и `api.giga.chat` вместе с системными сертификатами, `cleartextTrafficPermitted="false"`.

*Альтернатива:* официальный SDK. Для Kotlin/Android его нет (есть Python, JS, Spring), а REST-часть небольшая.

### 4. Ключ — один общий, из сборки

`GigaChatAuth` берёт ключ из `BuildConfig.GIGACHAT_AUTH_KEY`, который при сборке заполняется из `local.properties` (`gigachat.authKey`, файл вне git) через `buildConfigField`. Если поля нет, значение пустое: экран включения показывает «Помощник недоступен в этой сборке», `LlmProvider` не вызывается. Ключ не пишется в логи и не показывается в интерфейсе. Обфускация строки не добавляется: от извлечения из APK она не защищает, а только усложняет код.

*Альтернативы:* ввод своего ключа пользователем (было в ТЗ) и свой ключ как запасной вариант — отклонены решением пользователя; собственный сервер-прокси, который прячет ключ, — исключён ТЗ (нет сервера).

### 5. Настройки и учёт токенов — DataStore

Ключи: `ai_enabled`, `ai_hide_merchants`, `ai_tokens_used` (Long). Счётчик увеличивается на `usage.total_tokens` каждого ответа, включая промежуточные шаги цикла и подсказки категорий, и показывает только расход этого телефона. Предупреждения по счётчику нет: расход других телефонов по общему ключу неизвестен, а `GET /balance` для бесплатного тарифа недоступен. Конец лимита определяется по ответу 402.

### 6. История — таблица Room `chat_messages`, база версии 7

Столбцы: `id`, `role` (`USER`, `ASSISTANT`, `ERROR`), `text`, `tools` (коды выполненных инструментов для подписи, через запятую), `created_at`. Результаты инструментов не сохраняются. Сообщение `ERROR` хранит код ошибки для «Повторить» и в модель не отправляется. «Новый диалог» — `DELETE FROM chat_messages`. Миграция 6 → 7 только создаёт таблицу, тест миграции обязателен.

### 7. Экран «Помощник» — два состояния

`AssistantViewModel` собирает `ai_enabled`, историю и состояние запроса: **выключен** (экран включения с раскрытием данных; без ключа в сборке — «Помощник недоступен в этой сборке»), **чат** (сообщения, подсказки в пустом диалоге, индикатор «Думаю…», счётчик токенов в шапке, меню «Новый диалог»). Запрос выполняется в `viewModelScope`; при повороте экрана не прерывается. Если ответ пришёл, когда экран закрыт, он всё равно сохраняется в историю.

### 8. Подсказка категорий — один запрос на все черновики

`SuggestCategories` отправляет один запрос без инструментов: системный промпт с просьбой вернуть JSON `{"магазин": "категория"}`, в сообщении — до 20 названий черновиков без правила, вид операции и список имён категорий. Ответ разбирается в `ai`, категории сопоставляются по имени без учёта регистра, неизвестные отбрасываются. Подсказка хранится только в состоянии `DraftsViewModel` и ведёт себя как подсказка словаря: выбранный чип, пометка «Подсказал помощник», сохранение — по нажатию.

*Альтернатива:* подсказка автоматически при импорте. Отвергнута: запрос в сеть без действия пользователя и расход токенов на каждую покупку.

## Risks / Trade-offs

- [Модель неверно считает или выдумывает цифры] → в системном промпте запрет называть суммы, которых нет в результатах инструментов; все расчёты делает приложение; ответ — подсказка, а не операция.
- [Модель вызывает инструменты с неверными аргументами] → схема параметров с описаниями на русском, ошибки возвращаются модели текстом, предел 5 вызовов.
- [Название магазина — персональные данные] → раскрытие перед включением, режим «Не отправлять названия магазинов», в модель не уходят номера карт и тексты уведомлений.
- [Сертификат НУЦ Минцифры перестанет подходить или домены GigaChat изменятся] → адреса и сертификат в одном месте (`network_security_config`, константы клиента); ошибка TLS показывается как «Сервис GigaChat недоступен».
- [Условия бесплатного тарифа меняются; новых клиентов переводят на cloud.ru] → лимит — константа, проверяется по официальной странице тарифов при реализации; провайдер заменяем через `LlmProvider`.
- [Общий ключ извлекают из APK] → не предотвращается: ключ в git не попадает, ущерб ограничен лимитом бесплатного тарифа владельца, ключ можно перевыпустить в личном кабинете и пересобрать приложение.
- [Общий лимит бесплатного тарифа расходуют все пользователи; запросы идут от аккаунта владельца ключа] → понятное сообщение «Лимит помощника закончился, попробуйте позже», остальное приложение работает; перед публикацией приложения решение пересматривается (вопрос 5 раздела 17 ТЗ).

## Migration Plan

База 6 → 7: новая таблица, существующие данные не трогаются. Настройки ИИ появляются со значениями по умолчанию (выключено). `INTERNET` добавляется в манифест; до включения помощника сетевых запросов нет — это проверяется UI-тестом с подменным провайдером.
