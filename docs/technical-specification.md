# Техническое задание BudgetPlanner

## 1. Общая информация

**Название:** BudgetPlanner

**Версия документа:** 1.0, приведена в соответствие с реализацией 18.10.2026

**Целевая версия продукта:** 1.0

**Тип продукта:** Android-приложение, все данные хранятся только на телефоне

**Основной сценарий:** пользователь видит, сколько денег можно потратить сегодня, чтобы дожить до следующего дохода. Траты попадают в приложение автоматически из уведомлений банка или вводятся вручную.

BudgetPlanner не подключается к банку, не просит логины, пароли и данные карт и не может проводить операции. Приложение читает только текст уведомлений банковского приложения, которые и так появляются на экране телефона. Аккаунта и собственного сервера нет. Интернет нужен только для необязательного ИИ-помощника.

## 2. Цель продукта

Создать личный инструмент для контроля расходов, которым удобно пользоваться каждый день, потому что почти ничего не нужно вводить руками.

Версия 1.0 решает пять задач:

1. показать на главном экране одну понятную цифру: сколько можно потратить сегодня;
2. учитывать траты и доходы без ручного ввода, по уведомлениям банка;
3. заранее резервировать обязательные платежи: аренду, связь, подписки;
4. показывать, куда уходят деньги, по категориям и по дням;
5. отвечать на вопросы о расходах обычным языком через ИИ-помощника.

## 3. Границы системы

### 3.1 Компоненты

- Android UI на Jetpack Compose;
- доменный слой с расчётом бюджета, без зависимостей от Android;
- зашифрованная локальная база операций на Room и SQLCipher;
- сервис чтения уведомлений банков `NotificationListenerService` и парсеры текстов по банкам;
- ИИ-модуль с заменяемым провайдером модели, по умолчанию GigaChat;
- виджет рабочего стола на Glance;
- фоновые задачи на WorkManager: пересчёт дня, напоминания, очистка.

### 3.2 Схема работы

```text
+-------------------------------+
| Приложение банка              |
| показывает push-уведомление   |
+---------------+---------------+
                |
                v
+------------------------------------------------+
| BudgetPlanner                                  |
|                                                |
| NotificationListenerService                    |
|   -> фильтр по пакетам банков                  |
|   -> парсер банка -> операция, исходный текст  |
|      уведомления не сохраняется                |
|                                                |
| Domain: расчёт периода и «можно сегодня»       |
| Room + SQLCipher, DataStore, Android Keystore  |
| Compose UI, Glance-виджет, WorkManager         |
|                                                |
| AI: LlmProvider -> инструменты над локальными  |
|     данными                                    |
+-----------------------+------------------------+
                        |  только если ИИ включён:
                        |  вопрос, результаты
                        |  инструментов, названия
                        |  магазинов для подсказки
                        v
              +-------------------+
              | GigaChat API      |
              +-------------------+
```

### 3.3 Условия работы

- Android 10, API 29, и новее, `targetSdk` 37.
- Пользователь вручную выдаёт доступ к уведомлениям в системных настройках.
- Без интернета работает всё, кроме ИИ-помощника.
- Валюта версии 1.0: только рубли.

## 4. Термины

| Термин | Значение |
|---|---|
| Операция | Трата, доход, возврат, перевод или перевод себе с суммой, датой, категорией и источником |
| Источник | Как операция попала в приложение: вручную, из уведомления банка или корректировкой при сверке |
| Черновик | Операция из уведомления, которую пользователь ещё не подтвердил |
| Период | Отрезок от текущего дохода до следующего, например стипендии или зарплаты |
| Обязательный платёж | Плановый расход внутри периода, деньги на него резервируются заранее |
| Резерв | Сумма неоплаченных обязательных платежей до конца периода |
| Дневной лимит | Сколько в среднем можно тратить в день до конца периода |
| «Можно сегодня» | Дневной лимит минус сегодняшние траты |
| Правило категории | Запомненное соответствие «магазин или получатель → категория», отдельно для трат и для доходов |
| Перевод себе | Перевод между своими счетами в разных банках: не трата и не доход, в расчёт и статистику не входит |
| Остаток банка | Сумма на карте, которую банк указал в последнем уведомлении |
| Корректировка | Операция, которая выравнивает расчёт приложения с реальным остатком банка |
| Провайдер модели | Реализация интерфейса `LlmProvider`: GigaChat, YandexGPT или локальная модель |

## 5. Пользовательские сценарии

### 5.1 Первый запуск

1. Пользователь видит экран с объяснением: что делает приложение и что оно не получает доступ к банку.
2. Вводит, сколько денег у него сейчас есть на период, и доход: регулярный, каждый месяц в определённое число, или нерегулярный с датой следующего дохода.
3. Добавляет обязательные платежи до даты дохода или пропускает шаг.
4. Приложение предлагает включить автоимпорт: объясняет, какие уведомления читаются и что сохраняется, затем по шагам ведёт к нужным системным переключателям. Можно выбрать ручной ввод.
5. На Android 13 и новее предлагает разрешить уведомления приложения: перерасход, платёж накануне, новый период, расхождение с банком.
6. Предлагает защитить вход отпечатком, лицом или PIN-кодом телефона.
7. Открывается главный экран с суммой «можно сегодня».

### 5.2 Покупка с автоимпортом

1. Пользователь платит картой, банк присылает уведомление «Покупка 450 ₽, Пятёрочка».
2. Приложение распознаёт сумму, магазин и тип операции, не сохраняя исходный текст.
3. Если для магазина есть правило категории, операция сохраняется сразу. Если нет, создаётся черновик.
4. Сумма «можно сегодня» на главном экране и в виджете уменьшается сразу, черновик тоже входит в расчёт.

### 5.3 Подтверждение черновиков

1. На главном экране видна плашка «3 операции ждут категорию».
2. Пользователь выбирает категорию у нужных операций и нажимает «Сохранить». Галочкой «Запомнить» можно сохранить правило для магазина. Операции без выбранной категории остаются черновиками.

### 5.4 Ручной ввод

1. Пользователь нажимает «+», вводит сумму, выбирает категорию, при желании добавляет комментарий.
2. Операция сохраняется с источником «вручную».

### 5.5 Перерасход

1. Траты за день превысили дневной лимит.
2. Главный экран показывает перерасход цветом и текстом, приходит одно уведомление за день.
3. Завтра дневной лимит автоматически пересчитывается с учётом перерасхода.

### 5.6 Новый период

1. Наступает дата следующего дохода, либо из уведомления банка распознано зачисление, похожее на зарплату или стипендию.
2. Приложение предлагает начать новый период: подтвердить сумму и дату следующего дохода.
3. Итоги прошлого периода сохраняются в статистике.

### 5.7 Вопрос ИИ-помощнику

1. Пользователь спрашивает: «Хватит ли до стипендии, если куплю наушники за 3000?»
2. Модель вызывает локальный инструмент `simulate_purchase` с суммой 3000, получает новый дневной лимит и отвечает обычным языком.
3. В модель уходят вопрос, последние сообщения диалога и результаты инструментов, а не база операций.

### 5.8 Пополнение

1. Банк присылает уведомление «Зачисление 2 000 ₽».
2. Приложение записывает доход черновиком, бюджет периода и дневной лимит сразу растут.
3. Если зачисление пришло не дальше 3 дней от даты дохода, не меньше половины стартовой суммы или в тексте есть слова «зарплата», «стипендия», «аванс», приложение предлагает начать новый период.

### 5.9 Сверка с банком

1. Пришло уведомление «Покупка 450 ₽, Пятёрочка. Баланс 12 300 ₽».
2. По расчёту приложения на карте должно быть 12 750 ₽.
3. На главном экране появляется плашка «Расхождение с банком 450 ₽». Пользователь открывает её и выбирает: записать корректировку на сумму разницы, найти пропущенную операцию, ввести остаток вручную или пропустить.

## 6. Функциональные требования

### FR-01. Операции

- Создание, редактирование и удаление операций вручную.
- Поля: сумма, тип, дата и время, категория, магазин из уведомления, комментарий, источник, банк и последние 4 цифры карты. Типы: трата, доход, возврат, перевод, перевод себе. Трата, которой оплачен обязательный платёж, связана с этим платежом.
- При ручном вводе выбирается тип «Трата», «Доход» или «Возврат». Перевод вводится тратой в категории «Переводы». Сумма больше нуля и не больше 9 999 999,99 ₽, дата не позже сегодняшней, комментарий до 200 символов.
- Суммы хранятся целым числом копеек в `Long`, без `Double`.
- Удалённая операция сразу пропадает из расчётов. Отмена удаления через snackbar в течение 5 секунд. Удалённая операция из уведомления не появляется снова при повторной доставке того же уведомления.

### FR-02. Категории

- Категории трат по умолчанию: продукты, кафе и рестораны, транспорт, связь и интернет, развлечения, одежда, здоровье, подписки, переводы, другое. Категории доходов по умолчанию: стипендия, зарплата, перевод, подарок, другое.
- Свои категории с названием, иконкой и цветом. Название от 1 до 30 символов, без повторов внутри трат или доходов.
- Категорию по умолчанию или категорию с операциями нельзя удалить, только скрыть. Скрытую категорию можно вернуть.
- При вводе первыми идут категории, которые чаще использовались за последние 30 дней.

### FR-03. Период и «можно сегодня»

Расчёт выполняется в доменном слое чистой функцией и полностью покрывается unit-тестами.

- Доход бывает регулярным, каждый месяц в определённое число, или нерегулярным. Для регулярного дата следующего дохода подставляется сама, в коротком месяце это последний день месяца.
- Период длится от даты начала до даты следующего дохода. Дата следующего дохода в период не входит.
- `Бюджет периода` = стартовая сумма + доходы внутри периода. Возврат покупки уменьшает сумму трат, а не увеличивает доходы.
- Траты = траты и переводы минус возвраты. Переводы себе в расчёт не входят. Черновики из уведомлений входят в расчёт сразу.
- `Осталось дней` = число дней от сегодня до даты следующего дохода, включая сегодня, минимум 1.
- `Доступно на начало дня` = бюджет периода − все траты до сегодняшнего дня − резерв на начало сегодняшнего дня.
- `Дневной лимит` = доступно на начало дня / осталось дней, округление вниз до рубля.
- `Можно сегодня` = дневной лимит − траты за сегодня.
- Оплата обязательного платежа в пределах его суммы не уменьшает «можно сегодня»: деньги на него уже были в резерве. Превышение суммы платежа считается обычной тратой.
- Неожиданный доход внутри периода сразу пересчитывает лимит.
- Если «можно сегодня» меньше нуля, показывается перерасход.
- Когда наступила дата дохода, текущий период продолжается с одним оставшимся днём, пока пользователь не начнёт новый.
- Новый период начинается сегодня. Сумма заранее заполнена расчётным остатком без учёта сегодняшних операций, сегодняшние операции входят в новый период. Начать период можно и раньше даты дохода.
- Стартовую сумму и дату следующего дохода текущего периода можно изменить.
- Пересчёт при смене дня выполняется по фактической дате при каждом открытии приложения и сразу после полуночи, если приложение открыто. Виджет пересчитывается фоновой задачей после полуночи.
- Время берётся через внедряемый `Clock`, чтобы тесты могли управлять датой.

### FR-04. Обязательные платежи

- Список платежей: название, сумма, дата, повтор: разово или ежемесячно, категория трат, по умолчанию «Другое».
- Неоплаченные платежи с датой раньше даты следующего дохода входят в резерв, в том числе просроченные.
- Отметка «Оплачено» создаёт трату сегодняшним днём на сумму платежа в его категории. Ежемесячный платёж переносится на то же число следующего месяца, разовый помечается оплаченным. Удаление этой траты возвращает платёж в неоплаченные.
- Напоминание в 10:00 за день до даты платежа, если он не оплачен.

### FR-05. Автоимпорт из уведомлений

- Работает через `NotificationListenerService`, включается пользователем отдельно.
- Обрабатываются только уведомления от пакетов из списка поддерживаемых банков. Все остальные отбрасываются сразу, без записи куда-либо.
- Для каждого банка свой парсер, реализующий общий интерфейс `BankNotificationParser`: идентификатор банка `bankId`, набор пакетов `packageNames` и функция `parse`, которая возвращает разобранное уведомление `ParsedNotification` или ничего, если формат не распознан.
- Обрабатываются и списания, и пополнения:

  | Тип в уведомлении | Пример | Что делает приложение |
  |---|---|---|
  | Покупка, оплата, списание | «Покупка 450 ₽, Пятёрочка» | Трата: уменьшает «можно сегодня» и «осталось» |
  | Исходящий перевод | «Перевод 500 ₽, Олег К.» | Трата в категории «Переводы». Без правила создаётся черновиком |
  | Пополнение, зачисление, входящий перевод | «Зачисление 9 000 ₽» | Доход: увеличивает бюджет периода и дневной лимит. Если похоже на стипендию или зарплату, предлагает начать новый период, см. сценарий 5.6 |
  | Возврат, отмена покупки | «Отмена покупки 450 ₽» | Уменьшает сумму трат |
  | Перевод между своими счетами | «Перевод между счетами 1 000 ₽» | Игнорируется, если это видно по тексту |
  | Перевод себе в другой банк | «−5 000 ₽» в одном банке и «+5 000 ₽» в другом | Склеивается в «перевод себе», если вторая сторона пришла не позже чем через 10 минут: не трата и не доход, показывается в черновиках на подтверждение, можно разделить обратно. Если видна одна сторона, в черновике есть кнопка «Это перевод себе», имя отправителя или получателя можно запомнить как своё |

- Если в уведомлении указан остаток, например «Баланс 12 300 ₽» или «Доступно 12 300 ₽», парсер сохраняет его вместе с временем уведомления и последними 4 цифрами карты, если они есть. Остаток используется для сверки по FR-13.
- Исходный текст уведомления не сохраняется. В базу пишутся только разобранные поля.
- Защита от дублей: операция не создаётся, если уже есть операция с тем же ключом уведомления или того же банка с той же суммой, типом и магазином в пределах 2 минут.
- При подключении сервиса проверяются уже показанные уведомления через `getActiveNotifications`, чтобы не пропустить пришедшие, пока сервис был отключён. Уведомления старше 7 дней не обрабатываются.
- Настройки показывают состояние: «Автоимпорт работает», «Нет доступа к уведомлениям» или «Автоимпорт остановлен», кнопку следующего шага и список банков с отметкой, установлен ли банк. Если автоимпорт включали, а он остановился, на главной появляется плашка «Автоимпорт остановлен» с кнопкой «Исправить».
- Включение автоимпорта ведёт по шагам, нужным на этом телефоне: доступ к уведомлениям, снятие ограниченных настроек на Android 13 и новее при установке из файла, автозапуск и батарея на прошивках Xiaomi, Huawei, Honor, Samsung и других, которые выгружают фоновые сервисы.
- SMS и уведомления SMS-приложений не обрабатываются. Уведомление, которое не удалось разобрать, пропускается без сбоя.
- В отладочной сборке есть выключенный по умолчанию режим сбора образцов. Если включить, тексты уведомлений банков сохраняются в зашифрованной базе с замаскированными номерами карт, счетов, телефонов и другими числами из 4 и больше цифр, кроме сумм, и удаляются через 24 часа. В release-сборке режима нет.
- Поддерживаются Сбер, Т-Банк и Альфа-Банк. Парсер Т-Банка предварительный и уточняется по настоящим образцам. Каждый банк добавляется новым парсером без изменения других слоёв.

### FR-06. Автокатегоризация

- Подтверждая категорию черновика, пользователь может запомнить правило «магазин → категория».
- Новая операция из уведомления после проверки на перевод себе проверяется по правилам. Магазин сравнивается без учёта регистра, буквы «ё» и номеров терминалов. Если правило ведёт в скрытую категорию, создаётся черновик.
- Если правила нет, а магазин есть во встроенном словаре популярных магазинов, черновик получает категорию из словаря как подсказку с подписью «Знакомый магазин». Операция остаётся черновиком до подтверждения пользователем. Словарь применяется только к покупкам.
- Если ИИ включён и не выбрано «Не отправлять названия магазинов», на экране черновиков есть кнопка «Подсказать категории». Модель получает только названия магазинов, вид операции и список категорий, без сумм, дат и цифр карт. Подсказка с пометкой «Подсказал помощник» не применяется без подтверждения пользователя.
- Правила можно просматривать, менять и удалять с отменой в течение 5 секунд. Изменение правила не меняет уже сохранённые операции.

### FR-07. Статистика

- Расходы по категориям в виде кольцевой диаграммы. Режим «Период» охватывает текущий период по сегодня, режим «Месяц» охватывает календарный месяц с первого числа по сегодня. Режим действует на все блоки экрана. Если категорий больше пяти, показываются четыре крупнейшие и «Остальное». Нажатие на категорию открывает её операции за те же дни.
- Расходы по дням в виде столбчатой диаграммы. В режиме «Период» день, когда потрачено больше лимита этого дня, выделен цветом, пунктир показывает сегодняшний лимит. В режиме «Месяц» лимита на диаграмме нет.
- Сравнение с тем же числом первых дней прошлого периода, в режиме «Месяц» с теми же числами прошлого месяца: до трёх категорий с наибольшим изменением, где потрачено больше и меньше.
- Топ пяти магазинов по сумме с числом операций. Если магазины не указаны, блока нет.
- Итоги завершённых периодов: бюджет, потрачено, остаток или перерасход. Нажатие открывает статистику этого периода.

### FR-08. ИИ-помощник

- Чат с моделью. Диалог хранится в зашифрованной базе на телефоне, кнопка «Новый диалог» удаляет его после подтверждения.
- По умолчанию выключен. Пока помощник выключен, вкладка показывает экран включения со списком того, что уходит в модель и что остаётся на телефоне.
- Если в сборке нет общего ключа, вкладка показывает «Помощник недоступен в этой сборке», сетевых запросов нет.
- Модель не получает базу целиком. Она получает вопрос пользователя, последние сообщения текущего диалога и результаты локальных инструментов:

  | Инструмент | Параметры | Что возвращает |
  |---|---|---|
  | `get_period_status` | нет | Бюджет, резерв, потрачено, дневной лимит, «можно сегодня», дней до дохода |
  | `get_spending` | категория, начало и конец, все необязательны | Сумма и число операций |
  | `get_spending_by_category` | начало и конец | Суммы по категориям |
  | `get_top_merchants` | начало, конец, число магазинов | Магазины с наибольшими тратами |
  | `simulate_purchase` | сумма | «Можно сегодня», лимит с завтрашнего дня и остаток периода до и после гипотетической покупки |
  | `compare_periods` | нет | Разница по категориям с тем же числом первых дней прошлого периода |

  Если начало и конец не указаны, берутся начало текущего периода и сегодняшний день.
- Все инструменты только читают данные. Изменять операции через ИИ в версии 1.0 нельзя.
- На один вопрос выполняется не больше пяти вызовов инструментов, дальше чат просит переформулировать вопрос.
- Настройка «Не отправлять названия магазинов»: инструмент магазинов недоступен модели, остальные инструменты отдают только категории и суммы, подсказка категорий для черновиков отключена.
- Провайдер модели скрыт за интерфейсом `LlmProvider`, чтобы GigaChat можно было заменить на YandexGPT или локальную модель без изменения остального кода.
- Учёт токенов, израсходованных на телефоне. Расход других телефонов по общему ключу неизвестен, поэтому о конце лимита сообщает ответ сервера: чат показывает понятное сообщение.
- При ошибке сети, исчерпанном лимите или отказе сервера чат показывает понятное сообщение и кнопку «Повторить», вопрос остаётся в диалоге. Остальные функции приложения продолжают работать.

### FR-09. Виджет

- Glance-виджет: «можно сегодня», дней до дохода, кнопка быстрого добавления траты. В списке виджетов две карточки: 2×1, где только сумма, и 4×2, где сумма, доля потраченного лимита, дни до дохода и кнопка «+». Нажатие на виджет открывает главную. Если вход защищён, кнопка «+» сначала открывает экран блокировки. Пока данных нет, виджет показывает «Откройте BudgetPlanner».
- При защите входа сумма на виджете видна. Спрятать её можно переключателем «Прятать сумму на виджете» в разделе «Защита входа».
- Обновляется после каждого изменения операций и периода, операция из уведомления видна на виджете не позже чем через 3 секунды. При смене дня виджет пересчитывается без открытия приложения.

### FR-10. Защита входа

- Вход через разблокировку телефона: отпечаток, лицо, PIN, графический ключ или пароль телефона. Приложение не хранит свой PIN и данные биометрии. Защита включается в настройках, включение и выключение требуют проверки.
- Блокировка при холодном запуске и после ухода в фон на заданное время: сразу, через 1 минуту или через 5 минут. По умолчанию через 1 минуту. Перевод часов телефона на блокировку не влияет.
- Без блокировки экрана телефона защиту включить нельзя. Если блокировку экрана сняли, защита выключается и приложение один раз сообщает об этом.
- Настройка «Скрывать в недавних»: `FLAG_SECURE` прячет содержимое в списке недавних приложений и запрещает скриншоты. По умолчанию выключена и не зависит от защиты входа.

### FR-11. Экспорт и резервная копия

- Экспорт операций в CSV за выбранные даты, по умолчанию за текущий период. Файл открывается в Excel и «Google Таблицах» без настройки: UTF-8, разделитель «;», сумма в рублях со знаком. Столбцы: дата, время, тип, сумма, категория, магазин, комментарий, источник, банк, черновик. Цифры карт в файл не попадают, ячейки, похожие на формулу, выгружаются как текст. Место сохранения выбирает пользователь, доступ к памяти телефона не нужен.
- Резервная копия всех данных и настроек в файл, зашифрованный паролем пользователя. Пароль вводится дважды, не короче 8 символов, и не сохраняется. Ключ базы, счётчик токенов, отметки автоимпорта и образцы уведомлений в копию не входят.
- Восстановление после ввода пароля и подтверждения заменяет все данные и перезапускает приложение. Если новая база не открылась или запуск прервался, прежние данные возвращаются. Копия более старой версии переносится в текущий формат, копия более новой версии не принимается, при неверном пароле данные не меняются.
- Удаление всех данных: после подтверждения удаляются база, ключ и настройки, приложение открывает онбординг. Диалог предлагает сначала сделать резервную копию.

### FR-12. Уведомления приложения

- Перерасход дневного лимита, не чаще одного раза в день.
- Напоминание об обязательном платеже за день до даты, в 10:00, если платёж не оплачен.
- Предложение начать новый период: утром в день дохода и при зачислении, похожем на стипендию или зарплату. Каждое не чаще одного раза за период.
- Расхождение с банком, см. FR-13.
- Каждый тип отключается отдельно в настройках и в системных настройках Android, по умолчанию все включены. При защите входа содержимое уведомлений скрыто на экране блокировки телефона.

### FR-13. Сверка с банком

Нужна, потому что приложение не видит счёт и может разойтись с ним: оплата наличными, пропущенное уведомление, комиссия или автоплатёж без пуша.

- Точка отсчёта: первый остаток, пришедший в уведомлении по карте, или сумма, введённая пользователем вручную.
- `Ожидаемый остаток` = остаток в точке отсчёта + пополнения − списания по этой карте после неё. Черновики учитываются, корректировки не учитываются, перевод себе уменьшает остаток одной карты и увеличивает остаток другой.
- Каждый новый остаток из уведомления сравнивается с ожидаемым. Если разница больше 1 ₽, на главном экране появляется плашка «Расхождение с банком N ₽» и приходит уведомление.
- Варианты для пользователя: записать разницу корректировкой, открыть операции этой карты после прошлой сверки, чтобы найти пропущенную, ввести остаток вручную или пропустить. Если банк показывает меньше, корректировка записывается тратой в категории «Другое», если больше, доходом в категории «Другое».
- Корректировка без подтверждения пользователя не создаётся. Корректировка входит в расчёт «можно сегодня» как обычная операция.
- После решения и после совпадения точкой отсчёта становится последний остаток банка.
- Остатки разных карт сверяются отдельно по банку и последним 4 цифрам. Если банк не пишет цифры ни в одном уведомлении, все его операции считаются одной картой. Операция без цифр относится к карте банка, только если у этого банка одна карта. Операции, введённые вручную, составляют «Счёт без автоимпорта», который сверяется только вручную.
- Ручная сверка: кнопка «Сверить с банком» на экране периода, пользователь вводит реальный остаток, дальше тот же сценарий.
- Автоматическую сверку можно выключить в настройках. Остатки продолжают сохраняться без сравнения, ручная сверка доступна. При повторном включении точкой отсчёта становится последний сохранённый остаток.

## 7. Экраны

### 7.1 Онбординг

Объяснение продукта и приватности, ввод стартовой суммы и дохода, регулярного или нерегулярного, обязательные платежи, включение автоимпорта по шагам, разрешение уведомлений на Android 13 и новее, включение защиты входа.

### 7.2 Главный экран

- Крупно: «можно сегодня». Под ним дневной лимит, потрачено сегодня и дней до дохода.
- Прогресс периода: потрачено, резерв, осталось, ближайший обязательный платёж.
- Плашка расхождения с банком, если оно есть, см. FR-13. Она стоит выше плашки черновиков.
- Плашка черновиков, если они есть.
- Плашка нового периода в день дохода или после зачисления, похожего на доход.
- Плашка «Автоимпорт остановлен», если он перестал работать.
- Две последние операции и ссылка «Все».
- Кнопка «+» и кнопка настроек.

### 7.3 Операции

Список с группировкой по дням и итогом каждого дня, поиск по магазину, комментарию, категории и сумме, фильтр по категории и источнику. Список загружается порциями и догружается при прокрутке. Из сверки открывается фильтр по счёту с даты.

### 7.4 Операция

Создание и редактирование: тип, сумма, категория, дата и комментарий. Источник операции при редактировании не меняется.

### 7.5 Черновики

Очередь неподтверждённых операций с быстрым выбором категории, галочкой «Запомнить для» этого магазина и кнопкой «Сохранить N операций». Склеенные переводы себе подтверждаются или разделяются, у перевода с одной стороной есть кнопка «Это перевод себе». Если помощник включён, есть кнопка «Подсказать категории».

### 7.6 Статистика

Диаграммы и итоги из FR-07, переключатель «Период / Месяц». Нажатие на завершённый период открывает его статистику, нажатие на категорию открывает её операции.

### 7.7 Период и платежи

Текущий период, дата дохода, список обязательных платежей, кнопка «Начать новый период», кнопка «Сверить с банком», время последней сверки и состояние каждой карты.

### 7.8 ИИ-помощник

Экран включения со списком передаваемых данных. После включения: чат, подсказки готовых вопросов, подпись о расчёте под ответом, кнопка «Новый диалог», израсходованные токены.

### 7.9 Настройки

Автоимпорт и его состояние, автоматическая сверка с банком, ИИ-помощник: включение, «Не отправлять названия магазинов», израсходованные токены. Уведомления, защита входа. Бюджет: период, категории, правила для магазинов. Данные: экспорт в CSV, резервная копия, восстановление из копии, «Удалить все данные». В отладочной сборке есть раздел «Для разработки».

## 8. Архитектура

### 8.1 Общий подход

Clean Architecture и MVVM. Room и сетевой клиент не проникают во ViewModel и доменный слой. Android API во ViewModel допускается только для шагов включения автоимпорта.

- **domain:** модели, расчёт бюджета, use cases, интерфейсы репозиториев и `LlmProvider`, список банков, парсеры уведомлений и дедупликация. Чистый Kotlin, тестируется на JVM.
- **data:** Room, DataStore, реализация репозиториев, хранение ключа базы, резервная копия и запись файлов экспорта.
- **notifications:** сервис `BankNotificationListener`, приём уведомлений и фильтр пакетов.
- **ai:** клиент GigaChat, реализация инструментов, цикл «запрос → вызов функции → результат → ответ», подсказка категорий для черновиков.
- **reminders:** WorkManager, напоминания и уведомления приложения.
- **ui:** экраны Compose, ViewModel, навигация, тема.
- **widget:** Glance.
- **devtools:** демо-данные и сбор образцов уведомлений. Код лежит в `src/debug`, в `src/release` только пустые заглушки, поэтому в release-файле его нет.

### 8.3 Цикл ИИ-помощника

1. Приложение отправляет сообщения диалога и описания инструментов в поле `functions` с режимом `function_call: "auto"`.
2. Если модель возвращает `finish_reason: "function_call"`, приложение выполняет инструмент локально.
3. Результат добавляется в историю сообщением с ролью `function`, запрос повторяется.
4. Цикл ограничен 5 вызовами инструментов на один вопрос.
5. В запрос уходят системная подсказка, последние 10 сообщений диалога и результаты инструментов, база операций не отправляется.

| Ktor OkHttp engine 3.6.0 | Транспорт Ktor | Учитывает `network_security_config`, это нужно для сертификата Минцифры |

### 9.3 GigaChat API

- Получение токена: `POST https://ngw.devices.sberbank.ru:9443/api/v2/oauth`, заголовки `Authorization: Basic <ключ авторизации>` и `RqUID` со случайным uuid4, тело `scope=GIGACHAT_API_PERS`. Токен живёт 30 минут, кэшируется в памяти и обновляется заранее.
- Запросы к модели: `POST https://api.giga.chat/v1/chat/completions` с `Authorization: Bearer <токен>`. Модель GigaChat-2 Lite: у неё самый большой бесплатный лимит, вызов функций поддерживается.
- Вызов функций: поля `functions` и `function_call`, ответ с `function_call` и `finish_reason: "function_call"`, результат передаётся сообщением с ролью `function`.
- Для TLS нужен корневой сертификат НУЦ Минцифры. Он кладётся в `res/raw` и подключается в `network_security_config` через `domain-config` **только для доменов GigaChat**, а не для всего приложения.
- Используется один общий ключ авторизации приложения: он подставляется при сборке из `local.properties`. Этот файл исключён из git, ключ в репозиторий не попадает. Пользователь ключ не вводит и не видит.
- Общий ключ можно извлечь из APK, и все пользователи расходуют один лимит бесплатного тарифа владельца ключа. Решение пользователя от 16.10.2026: так и делаем, своего ключа в приложении нет. Перед публикацией приложения вопрос пересматривается, это вопрос 5 раздела 17.
- Бесплатный режим для физлиц: 365 млн токенов на 12 месяцев, один поток. С 1 сентября 2026 новых клиентов переводят на cloud.ru, доступность Freemium проверяется при регистрации.

## 10. Безопасность и приватность

### 10.1 Защищаемые данные

- история операций, суммы и магазины;
- остатки и бюджет;
- история диалога с ИИ-помощником;
- общий ключ авторизации GigaChat в сборке;
- ключ шифрования базы;
- остатки банка и последние 4 цифры карт: хранятся только в зашифрованной базе и не передаются в ИИ;
- файл резервной копии и файл экспорта CSV;
- образцы уведомлений в отладочной сборке.

### 10.2 Угрозы и меры

| Угроза | Мера |
|---|---|
| Приложение видит все уведомления телефона, включая мессенджеры | Обработка только пакетов из списка банков, остальное отбрасывается сразу, без логирования |
| Утечка текста уведомлений | Исходный текст не сохраняется. Образцы есть только в отладочной сборке, с маскировкой и удалением через 24 часа |
| Коды подтверждения из уведомлений | Не распознаются и не сохраняются. На Android 15 и новее система сама скрывает уведомления с одноразовыми кодами от сторонних приложений |
| Чтение базы с украденного или рутованного телефона | База зашифрована SQLCipher, ключ защищён Android Keystore |
| Данные в облачной резервной копии Android | База, ключ и настройки исключены из автобэкапа и переноса на новый телефон: `allowBackup="false"`, `dataExtractionRules` |
| Посторонний открыл приложение на разблокированном телефоне | Вход через разблокировку телефона, блокировка при уходе в фон, уведомления приложения скрыты на экране блокировки телефона |
| Скриншоты и список недавних приложений | Настройка «Скрывать в недавних» включает `FLAG_SECURE` |
| Утечка файла резервной копии | Файл зашифрован паролем пользователя, пароль не сохраняется |
| Формулы в файле CSV | Ячейки, похожие на формулу, выгружаются как текст, цифры карт в файл не попадают |
| Отправка финансовых данных стороннему сервису | ИИ выключен по умолчанию. В модель уходят вопрос, последние сообщения диалога и результаты инструментов, для подсказки категорий только названия магазинов. Есть режим без названий магазинов |
| Перехват трафика к модели | Только HTTPS. Российский корневой сертификат доверяется только для доменов GigaChat |
| Утечка ключа GigaChat через репозиторий | Общий ключ только в `local.properties` вне git и подставляется при сборке. Извлечение общего ключа из APK не предотвращается, ущерб ограничен лимитом бесплатного тарифа |
| Логи с персональными данными | Суммы, магазины и тексты не пишутся в Logcat в release-сборке |

### 10.3 Чего приложение не делает

- не подключается к банку и не хранит данные для входа в банк;
- не читает SMS, разрешение `READ_SMS` не запрашивается;
- не запрашивает доступ к контактам, памяти телефона и местоположению;
- не отправляет данные никуда, кроме модели ИИ, и только когда пользователь её включил. Файлы экспорта и резервной копии сохраняются только туда, куда укажет пользователь;
- не содержит аналитики и рекламы.

## 11. Android-разрешения

| Разрешение | Зачем | Когда |
|---|---|---|
| `BIND_NOTIFICATION_LISTENER_SERVICE` | Автоимпорт, разрешение объявлено у сервиса | Пользователь выдаёт в системных настройках |
| `POST_NOTIFICATIONS` | Перерасход, платежи, новый период, расхождение с банком | На Android 13 и новее: шаг онбординга «Подсказки вовремя» или кнопка «Разрешить» в настройках |
| `USE_BIOMETRIC` | Вход через разблокировку телефона | Выдаётся при установке, проверка запускается при включении защиты и при входе |
| `INTERNET` | Только ИИ-помощник | Есть в манифесте, используется только при включённом ИИ |

Библиотеки добавляют служебные разрешения без доступа к данным пользователя: `USE_FINGERPRINT` для биометрии, `WAKE_LOCK`, `RECEIVE_BOOT_COMPLETED` и `FOREGROUND_SERVICE` для фоновых задач. `ACCESS_NETWORK_STATE` удалён из сборки, из сетевых разрешений есть только `INTERNET`. В манифесте объявлены пакеты банков из списка, чтобы проверить, установлено ли приложение банка. Доступа к списку всех приложений нет.

## 12. Нефункциональные требования

### NFR-01. Производительность

- Главный экран открывается с актуальной суммой быстрее чем за 1 секунду на устройстве среднего уровня.
- Операция из уведомления появляется в приложении и виджете в течение 3 секунд.
- База на 50 000 операций не замедляет списки и статистику заметно для пользователя: список операций загружается порциями по 300 операций, первая порция, обновление, поиск и расчёт главной занимают меньше 1 секунды.

### NFR-02. Надёжность

- Расчёт «можно сегодня» детерминирован и покрыт тестами на границы: последний день периода, смена месяца, перерасход, доход внутри периода, оплата обязательного платежа.
- Миграции Room покрыты тестами, данные не теряются при обновлении.
- Сбой парсера на неизвестном формате не роняет сервис, уведомление просто пропускается.

### NFR-03. Приватность

Все требования раздела 10. Без интернета приложение работает полностью, кроме ИИ.

### NFR-04. UX и доступность

- Светлая и тёмная тема, Material 3.
- Поддержка TalkBack: суммы озвучиваются полностью, например «четыреста пятьдесят рублей».
- Крупный шрифт до 200 % не ломает основные экраны: подписи переносятся между словами или немного уменьшаются, крупная сумма на главной подбирает размер под ширину карточки.
- Сумма «можно сегодня» понятна без объяснений: цвет плюс текст, а не только цвет.

### NFR-05. Совместимость

- Android 10–17, уровни API 29–37.
- Проверка на эмуляторах API 29 и API 37 и на реальном телефоне с банковским приложением.

## 13. Тестирование

### 13.1 Unit-тесты

- `BudgetCalculator`: все формулы FR-03 и граничные случаи.
- Парсеры банков: тексты уведомлений как фикстуры, включая отмены, возвраты, коды подтверждения и неизвестные форматы. У Альфа-Банка это настоящие замаскированные уведомления, у Сбера и Т-Банка типичные форматы до сбора настоящих образцов.
- Дедупликация.
- Сверка: ожидаемый остаток, порог расхождения, корректировка в обе стороны, новая точка отсчёта, несколько карт, уведомления без остатка.
- Цикл ИИ: вызов функций, ограничение числа вызовов и обработка ошибок на подставном `LlmProvider`. Клиент GigaChat: формат запросов, токен и ошибки сервера через Ktor MockEngine.
- Экспорт CSV: формат, экранирование, защита от формул.
- Статические проверки безопасности: манифест, правила бэкапа, сетевая конфигурация, журнал, зависимости.

### 13.2 Тесты UI и интеграции

- Главный экран: пересчёт после добавления операции.
- Черновики: подтверждение и запоминание правила.
- Миграции Room.
- Сервис уведомлений: instrumented-тест обработки пакета банка и игнорирования чужого пакета.
- Доступность: автоматическая проверка основных экранов, крупный шрифт 200 % на главной и в новой операции.
- Скорость: список, поиск и расчёт главной на 50 000 операций меньше 1 секунды, операция из уведомления в приложении и виджете меньше 3 секунд.
- Шифрование базы, резервная копия и восстановление на настоящей SQLCipher, включая откат при прерванном восстановлении.
- Unit-тесты и отладочная сборка запускаются в GitHub Actions при каждом пуше.

## 14. Критерии готовности версии 1.0

- Главный экран корректно показывает «можно сегодня» во всех граничных случаях FR-03.
- Покупка по карте поддерживаемого банка появляется в приложении автоматически, без ручного ввода.
- Чужие уведомления не сохраняются нигде, это проверено тестом.
- База зашифрована, исключена из облачного бэкапа, вход защищён.
- ИИ отвечает на вопросы из FR-08 через инструменты и не получает базу целиком.
- Виджет работает и обновляется.
- Списания и пополнения поддерживаемого банка попадают в приложение автоматически, расхождение с остатком банка обнаруживается и исправляется по сценарию 5.9.
- Все тесты проходят на API 29 и API 37.

## 15. Что не входит в версию 1.0

- несколько валют;
- несколько пользователей и семейный бюджет;
- синхронизация между устройствами и облачный бэкап;
- подключение к банкам по API;
- чтение SMS;
- изменение данных через ИИ;
- инвестиции, кредиты, долги;
- поддержка банков сверх Сбера, Т-Банка и Альфа-Банка: архитектура готова, новые парсеры добавляются позже;
- автоматическая отметка обязательного платежа по уведомлению банка: в версии 1.0 платёж отмечается вручную;
- показ источника «из уведомления банка» и магазина в редакторе операции.

## 16. Этапы реализации

Каждый этап оформляется отдельным OpenSpec change. Этапы с 1 по 11 выполнены. В этапе 12 остались проверки на телефоне пользователя: TalkBack, скорость автоимпорта, сбор настоящих образцов уведомлений, переход на release и сверка с критериями раздела 14.

1. **establish-foundation:** проект, пакеты, Hilt, тема, навигация, тесты на API 29 и 37.
2. **add-operations-and-categories:** Room, операции, категории, ручной ввод, список.
3. **add-period-and-daily-limit:** период, обязательные платежи, `BudgetCalculator`, главный экран. После этого этапа приложением уже можно пользоваться каждый день.
4. **add-statistics:** диаграммы и итоги периодов.
5. **add-data-protection:** SQLCipher, Keystore, исключение из бэкапа, вход по биометрии.
6. **add-notification-import:** сервис, парсеры Сбера, Т-Банка и Альфа-Банка, черновики, дедупликация, режим сбора образцов.
7. **add-balance-reconciliation:** остаток из уведомлений, `BalanceReconciler`, плашка расхождения, корректировки, ручная сверка.
8. **add-auto-categorization:** правила по магазинам.
9. **add-widget-and-reminders:** Glance, WorkManager, уведомления приложения.
10. **add-ai-assistant:** `LlmProvider`, клиент GigaChat, инструменты, чат.
11. **add-animations:** анимации интерфейса: изменение сумм и полосок, появление плашек, переходы между экранами; учёт системной настройки «Убрать анимацию».
12. **harden-and-release-v1:** обновление зависимостей, экспорт CSV, резервная копия и восстановление, удаление всех данных, доступность, производительность, проверка безопасности, release-сборка с R8 и подписью, инструменты разработки только в отладочной сборке.

## 17. Открытые вопросы

1. ~~Какой банк поддержать первым?~~ Решено: первым Сбер, затем Т-Банк и Альфа-Банк. Тексты уведомлений для парсера собираются режимом сбора образцов в отладочной сборке.
2. ~~Финальное название приложения.~~ Решено: «BudgetPlanner».
3. ~~Доход регулярный или нерегулярный?~~ Решено на этапе add-period-and-daily-limit: поддерживаются оба варианта. Регулярный доход приходит каждый месяц в определённое число, дата подставляется сама. При нерегулярном пользователь вводит дату следующего дохода.
4. ~~Несколько карт и счетов учитывать как один общий бюджет или раздельно?~~ Решено: один общий бюджет, сверка с банком отдельно по каждой карте. Переводы между своими счетами в разных банках не считаются ни тратой, ни доходом: пара «ушло» и «пришло» склеивается сама, одна сторона отмечается кнопкой «Это перевод себе», отправитель запоминается.
5. Публиковать ли приложение в RuStore или F-Droid? Вопрос отложен пользователем, release-сборка от ответа не зависит. Исходный код открыт на GitHub под лицензией GPL-3.0.
6. Пишут ли банки остаток в уведомлениях? Если нет, остаётся только ручная сверка. Пока известно: в двух настоящих уведомлениях Альфа-Банка, о списании со счёта и о зачислении по СБП, остатка нет. Настоящих образцов Сбера и Т-Банка ещё нет.
7. ~~Поддерживать ли SMS банка через уведомление SMS-приложения?~~ Решено: нет, обрабатываются только push-уведомления банковских приложений.
